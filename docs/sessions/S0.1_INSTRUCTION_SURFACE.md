## Why this session exists

`AGENTS.md` has been reported as over-specific — slowing sessions down, making them less
adaptable. That report is **unverified**, and it is not the thing to act on. The measurable
problem is different and provable from the repo's own history:

- The file mixes four genres with no marking: binding invariants, expensive empirical findings,
  incident narrative, and one-off prohibitions.
- It has gone stale at least once in a way that was caught only by accident
  (`DESIGN_RULES_AUDIT.md` records a row referencing `npm run wraps:all`, a script that no longer
  existed).
- Docs in this repo rot in bulk when unverified: one audit pass found 88 of 102 `theme.*`
  accesses dead across five library docs, plus two components documented in full that **never
  existed in this repo**.

So the job is not "shorten it." It is: **establish which claims are still true, then move each
one to the place it will actually be read.** Length is an output of that, not a target.

**Nothing is deleted for being long.** A claim is removed only when it is (a) provably false
against the code, or (b) relocated to a named destination recorded in the ledger.

## Phase A — Inventory and verify (read-only; no file is modified in this phase)

Produce `docs/audit/INSTRUCTION_SURFACE_AUDIT.md`. Every claim in `AGENTS.md` gets one row.

| col | meaning |
|---|---|
| `id` | A1, A2, … stable reference for later phases |
| `lines` | line range in `AGENTS.md` at the session's starting commit |
| `genre` | `invariant` \| `finding` \| `narrative` \| `prohibition` |
| `subject` | the file, script or component it governs — `file:line` where one exists |
| `status` | `true` \| `false` \| `unverifiable` |
| `evidence` | what was read to decide `status` |
| `destination` | proposed target (see Phase B) |

Genre definitions — apply these literally, do not improvise a fifth:

- **invariant** — a rule that binds future work regardless of context. *"Migrations in `lib/db.ts`
  are append-only; `PRAGMA user_version` indexes into the array."*
- **finding** — knowledge that cost measurement to obtain and cannot be re-derived by reading the
  code. *The `measureInWindow` / Fabric `includeViewportOffset` behaviour; pixelmatch being blind
  to differences between two near-black colours.*
- **narrative** — who reported what, when a ruling reversed, what a past pass did. True, dated,
  and not needed at read time.
- **prohibition** — "don't do X." Every one of these gets a **reason** and a **scope**. A
  prohibition whose reason cannot be located is not deleted — it is marked `unverifiable` and
  raised at the STOP gate.

**Verification rule:** a claim is `true` only if the session read the code, script or test it
describes. A claim believed from the surrounding prose is `unverifiable`, not `true`. Do not mark
anything `false` without quoting the contradicting source.

**Do not fix anything found `false` in this session.** Record it. Fixing stale-doc findings mixes
two changes in one diff and is Phase 1 work.

## Phase B — Relocate

`AGENTS.md` **stays**, at its path, as a short router — it is the conventional entry point a
coding agent looks for, and moving it would silently orphan every existing session prompt. It
ends this session containing: a one-paragraph statement of what the app is, the four destinations
below with one line each on when to read them, and nothing else.

Destinations, in priority order. A claim goes to the **first** one that fits:

1. **A comment at the call site** — anything governing one function, component or script. This is
   the strongest destination available and the default for `finding` and scoped `prohibition`
   rows. Precedent: a past session correctly consulted `Surface.tsx`'s own docstring rather than
   the library doc that described it.
2. **A test** — anything mechanically checkable. Prefer extending an existing suite in
   `lib/__tests__/` over adding a file. A source-scan test is acceptable here; this session is
   not the place to argue about allowlists.
3. **`HARNESS.md`** (new) — how to read each audit's output. This is where every harness quirk
   lives: `halos` non-determinism, `wraps`' known false positives and the ones that must not be
   "fixed", `visual`'s `MACHINE_DEPENDENT` and `WANTED_BUT_UNCAPTURED` lists, `geometry`'s
   sub-tolerance skew, and which harnesses are structurally blind to what.
4. **`INVARIANTS.md`** (new) — rules a session must hold *before* touching anything. Target:
   **under 400 lines**. If it exceeds that, the overflow is not invariant; re-genre it.
5. **`docs/archive/AGENTS_HISTORY.md`** — all `narrative`, moved verbatim, with a header stating
   it is dated history and must not be read as current.

**Constraints:**
- **No claim appears in two destinations.** If a rule is in `INVARIANTS.md`, its call site
  comment points there rather than restating it.
- Every prohibition that survives carries its **date and reason** inline.
- The audit table from Phase A is updated with the destination each row actually landed in, so
  the ledger is closed. A row with no destination at the end of the session is a defect.

## Phase C — Prove nothing moved

1. `npx tsc --noEmit` — must match the Phase A baseline **exactly** (same count, same errors).
2. `npm run lint` — must match baseline.
3. `scripts/test-changed.sh --all` — same suite/test counts, plus any tests added in Phase B
   step 2, each of which must be shown to **fail** against a deliberately broken probe and pass
   when reverted.
4. `git diff --stat` — every change is a `.md` file, a comment-only change to a source file, or a
   new/extended test. **A source diff that changes a single executable line means this session
   went wrong.** Report it rather than reverting quietly.

## STOP gates — end the session and report, do not resolve

- Any claim marked `false` that governs shipped behaviour (as opposed to a stale script name).
- Any `prohibition` whose reason cannot be located. It may be load-bearing; a maintainer decides.
- Any claim that turns out to encode a **design decision** rather than a technical constraint —
  those go to `DECISIONS_OPEN.md`, and this session does not write that file.
- `INVARIANTS.md` cannot be brought under 400 lines without dropping something the session judges
  binding.
- Anything requiring a device to verify. Note it; do not guess.

---

## Explicitly out of scope

- Fixing anything Phase A found stale.
- Any change to `components/` or `app/` beyond comments.
- Touching `REBUILD_DECISIONS.md`, `DECISIONS_OPEN.md`, `PROJECT_VISION.md` or
  `DESIGN_RULES.md` — planning files are read-only in a coding session.
- Shortening `AGENTS.md` by deleting content. Only relocation reduces it.
- Adding or removing a dependency.
